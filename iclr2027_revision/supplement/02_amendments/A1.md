## 0. Why this is a valid pre-registration, not a post-hoc choice

No metric on any pre-registered hypothesis has been computed on any screen. Sessions
L8b, L9, and L9.1 each printed `METRIC_ON_HYPOTHESIS: NO` / `METRIC_COMPUTED: NO`, and
no model has been fitted (`MODEL_FIT_EXECUTED: NO` in all three). This amendment is

**Binding consequence of that blindness.** If the primary definition adopted below

It will be reported as the primary finding. Reversing the ordering after seeing the
numbers would void the pre-registration and must not be done.

## 1. The finding that motivates the amendment

`x_release` — the external expression comparator in the submitted manuscript — is the
Replogle release's `normalized_bulk` matrix `a.X`, loaded **raw**
(`scripts/phase11b_classical_transfer/run.py:80-118`): no CP10K, no `log1p`, no
NT-subtraction. Symbol-mapped into the VCC-HVG namespace, then `nan_to_num`, then
clipped to ±10.

It is **not** the same quantity as VCC's `x`:

- A log1p-CP10K delta is bounded within ±log(10⁴+1) ≈ **±9.21**. `x_release` contains
  native values of **40.5** (K562), **179.4** (RPE1), and **+∞** (253 entries, RPE1);
  49 / 483 native values exceed 9.21. This is a **hard mathematical bound**, not a
  ratio argument — the identification is decisive.
- Per-construct spread ratio `x_release / x_cell`: **MAD 2.75 / 2.94**, **IQR 2.73 /
  2.93** (RPE1 / K562). Tail-insensitive, so immune to the ±10 clip.
- It is not even a clean constant rescale: OLS slope 2.07–2.41 < std ratio 2.30–2.60 <
  MAD/IQR 2.75–2.94, with per-construct Pearson 0.91–0.93. A different quantity with
  scatter, so "multiply by a constant" is not an available repair.
- VCC `x` and `x_cell` sit on the **same** scale (row-MAD 0.041 vs 0.047 / 0.030).
  `x_release` is the outlier.

**Downstream consequence.** A VCC-fit head scored zero-shot on the externals receives
`m̃` inputs whose median sits **+2.2 to +4.0 SD** above VCC-train (RPE1), with
**33–40 %** of RPE1 rows outside the VCC-train observed range (K562: ~6 %). For the
linear head an approximately-common rescale is approximately Spearman-preserving and
this matters little. For the tree ensembles it matters a great deal and is not
arguable: every split threshold lies inside the training range, so any input beyond the
training maximum falls in the same leaf as the training maximum. A third to two fifths
of RPE1 rows would be compressed together and left mutually indistinguishable. The
manuscript's best VCC model is `RF[x; m̃]`.

## 2. The amendment

For **both** external screens (RPE1, K562-essential), the external expression baseline
`x` and the external magnitude block `m̃` are defined as follows:

- **PRIMARY: `x_cell`** — the construction-matched per-construct delta,
  `mu_construct − mu_NT` over native `cp10k_log1p`, symbol-mapped to the VCC-HVG
  namespace, zero-filled, `nan_to_num`, clipped ±10 last. Same units as VCC `x`; same
  construction pipeline as `z`. Available for both screens (Phase 2 → RPE1, Phase 3 →
  K562-essential, both QC-accepted).
- **SECONDARY: `x_release`** — as submitted, unchanged. Reported alongside, in full, in
  the appendix.

Both are reported for every external arm they enter. Neither is dropped.

**Scope.** This governs the external `[x]` and `[x; m̃]` arms and the external `m̃`
block wherever it appears. It does **not** touch:

- VCC — `x` on VCC is unchanged, unclipped, and internally consistent; `m̃` on VCC
  passed its oracle against the manuscript's own `magnitude_augment.py`
  (NUMERICALLY_EQUIVALENT, 1.31e-6 post-z-score, float32 floor).
- `z` — unchanged on every screen, and already construction-matched.
- The z-scoring convention — still `StandardScaler` fitted on **VCC train only**,
  frozen, applied unchanged everywhere (§6B).
- The **exactly one new result** constraint. The one new result remains the
  Geneformer arm. This is a sensitivity analysis on one feature block, not a result.

## 3. A falsifiable prediction, recorded in advance

If the diagnosis in §1 is correct, recomputing `m̃` on `x_cell` should bring the
externals substantially back inside the VCC-train range, because `x_cell` and VCC `x`
share a scale.

**Prediction:** the out-of-range row counts on RPE1 — currently `mean|x|` 435,
`‖x‖₂/√d` 760, `‖x‖∞` 637, `σ` 763 out of 1,932 — should fall by a large margin under
`m̃(x_cell)`.

**What refutes it:** if those counts do not fall materially, then the out-of-range
behaviour is not caused by the units mismatch, the diagnosis in §1 is incomplete, and
this amendment's rationale must be revisited before Phase 4 proceeds. Record the
observed counts either way.

## 4. What the manuscript must disclose

Not optional, and not a footnote:

1. What `x_release` is — the release's `normalized_bulk`, raw, not a log1p-CP10K delta.
   The submitted text does not say this.
2. That it is on a different scale from the VCC training features (~2.7–2.9× in MAD),
   and that the only magnitude reconciliation on that path is a ±10 clip.
3. That the primary external analysis therefore uses the construction-matched `x_cell`,
   with `x_release` reported in full as a secondary analysis.
4. That this is a **deviation from the submitted version**, with this amendment's date
   and the fact that it was committed before any external number was computed.

Framed correctly this is a strength in a revision: a concrete methodological
improvement, found by the authors, disclosed by the authors, with both analyses shown.

## 5. Open item carried forward

`x_cell` exists only because it was built for this revision. The submitted paper's
external results — already in the rejected version — were computed on `x_release`. If
the two analyses disagree materially, the revision must say so plainly rather than
